# The 65C832

The core is a 65C832: WDC's 32-bit member of the family (the W65C832
preliminary data sheet, March 1990), which runs 6502 and 65C816 code
unchanged and adds a native mode with a 32-bit accumulator and 32-bit index
registers. To that it adds instructions of its own, behind the WDM opcode
($42): multiply, divide, multi-bit shifts and rotates, and a byte swap.

WDC never made the part, and its data sheet is a lightly edited 65C816
one: it leaves things out and contradicts itself in places. Where it is
silent this core decides, always so that 65C816 code runs exactly as
before; those decisions are marked *(decided)*.

Both halves are optional at build time (see "Building"): without them the
core is the 65C816 it was.

## Modes

Two hidden bits select the mode, **E16** and **E8**. E8 is the 65C816's E
bit. Reset sets both.

| E16 | E8 | mode | A (M=0) | A (M=1) | X, Y (X=0) | X, Y (X=1) |
|---|---|---|---|---|---|---|
| 1 | 1 | 6502 emulation | 8 | 8 | 8 | 8 |
| 1 | 0 | 65C816 native | 16 | 8 | 16 | 8 |
| 0 | 0 | 65C832 native | 16 | 8 | 32 | 8 |
| 0 | 1 | 65C832 native | 32 | 8 | 32 | 8 |

This is the data sheet's Table 1-1. In 65C832 native mode M and X choose
between 8 bits and the wide width, as on the 65C816, and E8 picks the
accumulator's wide width, 16 or 32. Index registers are 8 or 32 bits there:
there is no 16-bit index in 65C832 mode.

Two instructions exchange the hidden bits with flags:

| | | |
|---|---|---|
| `XCE` | $FB | C and E8 exchanged (as on the 65C816) |
| `XFE` | $42 $FB | C and E8, and V and E16, exchanged together |

The data sheet names XFE but gives it no opcode; it is here a WDM-prefixed
instruction *(decided)*, so `XCE` is untouched and 65C816 code that leaves
or enters emulation with `SEC`/`CLC` and `XCE` behaves as it always did.
With E16 = 1, XCE moves between emulation and 65C816 native mode as on the
65C816; with E16 = 0 it switches the accumulator between 16 and 32 bits.

From 65C816 native mode into 65C832 native mode, a 32-bit accumulator:

    sec          ; E8 := 1: the accumulator 32 bits wide
    clv          ; E16 := 0: 65C832 native
    xfe          ; C := the old E8 (0), V := the old E16 (1)

and back:

    clc          ; E8 := 0
    sep #$40     ; E16 := 1 (V set; there is no SEV)
    xfe

Since XFE leaves the old E8 and E16 in C and V, `XFE` then `PHP` saves the
mode, and `PLP` then `XFE` restores it.

On entering emulation mode (by XCE or XFE) M and X become 1, S's high byte
$01, and X and Y their low bytes, as on the 65C816. On entering 65C816
native mode from 65C832 mode, X and Y keep their low 16 bits *(decided)*.

## Registers

A, X and Y are 32 bits; S, D and PC 16; DBR and PBR 8, as on the 65C816.
P is the same 8 bits.

- **A** keeps the bits above its width: as B, the high byte, survives 8-bit
  operations on the 65C816, so bits 16-31 survive 16-bit ones and bits
  8-31 8-bit ones.
- **X and Y** hold nothing above their width: an 8-bit index register is
  0-255, a 16-bit one 0-65535 *(decided for the 16/32 boundary; the
  65C816 does the same at 8/16)*.
- Flags come from the width an instruction works at: N is bit 7, 15 or
  31; Z tests 8, 16 or 32 bits; V of ADC, SBC and BIT is bit 6, 14 or 30
  of the operand's sign arithmetic.

### What a wide register changes

| | |
|---|---|
| immediates | as wide as the register: `LDA #` is 2, 3 or 5 bytes, `LDX #` 2, 3 or 5 |
| memory operands | as wide as the register, low byte first, at the address and the next ones |
| read-modify-write (ASL ... TRB on memory) | A's width |
| `PHA`/`PLA`, `PHX`/`PLX`, `PHY`/`PLY` | 1, 2 or 4 bytes |
| `PHP`, `PHB`, `PHK`, `PHD`, `PEA`, `PEI`, `PER`, `PLP`, `PLB`, `PLD` | unchanged (1 or 2 bytes) |
| decimal mode | ADC and SBC work on 2, 4 or 8 BCD digits |
| `BIT` | N and V from bits 31 and 30 at 32 bits |

Transfers take the whole source register and store as much of it as the
destination holds (data sheet 8.21); flags are of the destination's width.
`TAX` with a 16-bit accumulator and 32-bit X copies all 32 bits of A. The
data sheet makes four transfers 16-bit whatever the width:

| | |
|---|---|
| `TCS`, `TCD` | A's low 16 bits into S or D |
| `TSC`, `TDC` | S or D into A's low 16 bits; bits 16-31 kept *(decided)*; N and Z of 16 bits |
| `TSX` | S into X, zero-extended |
| `TXS` | X's low 16 bits into S |
| `XBA` | A's two low bytes exchanged; bits 16-31 kept |

### Addressing

Addresses are still 24 bits. A 32-bit index register adds all of its low
24 bits:

| | |
|---|---|
| `abs,X`, `abs,Y`, `long,X`, `(dp),Y`, `[dp],Y`, `(sr,S),Y` | the base plus the index, modulo 2^24: one instruction reaches all 16 MB |
| `dp,X`, `dp,Y`, `(dp,X)` | D + dp + index, modulo 2^16, in bank 0 (or D's bank in banked mode) |
| `(abs,X)` jumps | abs + index, modulo 2^16, in the program bank |

### Block moves

`MVN` and `MVP` address bank:0000 plus X (source) and Y (destination),
modulo 2^24 *(decided)*; with 8- or 16-bit index registers that is the
65C816's bank:X. The count is A at its wide width: 16 bits, or 32 with E8 = 1
in 65C832 mode, so a 32-bit move can cross banks and be longer than 64 KB.

## Interrupts

The data sheet gives 65C832 native mode vectors of its own:

| | emulation | 65C816 native | 65C832 native |
|---|---|---|---|
| COP | $FFF4 | $FFE4 | $FFD4 |
| BRK | $FFFE | $FFE6 | $FFD6 |
| ABORT | $FFF8 | $FFE8 | $FFD8 |
| NMI | $FFFA | $FFEA | $FFDA |
| (reserved) | | | $FFDC |
| IRQ | $FFFE | $FFEE | $FFDE |

An interrupt in 65C832 native mode pushes PBR, PC and P as in 65C816
native mode, and changes neither E16 nor E8. They are not pushed, so a
handler runs in the mode and widths of the code it interrupted, and RTI
must be executed in that mode (data sheet 8.12.3). A handler that wants
65C816 native mode saves A, X and Y whole first (in 65C832 mode, with
`REP #$30` for 32-bit index registers), then switches with XFE and PHP
(above), and undoes both before RTI.

## The extension: WDM-prefixed instructions

WDM ($42) is a prefix. With the byte after it, it makes one instruction:
an interrupt comes before the $42 or after the whole instruction, and an
ABORT retries it from the $42. The extension works in every mode, at the
accumulator's width (8, 16 or 32).

| bytes | | operation |
|---|---|---|
| $42 $FB | `XFE` | C and E8, V and E16 exchanged (above) |
| $42 $EB | `BSW` | A's bytes in reverse order, at its width; N, Z |
| $42 $0A *n* | `ASL #n` | A shifted left *n* bits |
| $42 $4A *n* | `LSR #n` | A shifted right *n* bits |
| $42 $8A *n* | `ASR #n` | A shifted right *n* bits, the sign copied in |
| $42 $2A *n* | `ROL #n` | A rotated left *n* bits, not through C |
| $42 $6A *n* | `ROR #n` | A rotated right *n* bits, not through C |
| $42 + an ADC opcode | `MUL` | X:A := A × M, signed |
| $42 + an AND opcode | `UML` | X:A := A × M, unsigned |
| $42 + a CMP opcode | `DIV` | A := A DIV M, X := A MOD M, signed |
| $42 + an EOR opcode | `UDV` | A := A DIV M, X := A MOD M, unsigned |
| $42 $B1, $42 $B0 | | banked direct page and stack on, off ([BankedDP.md](BankedDP.md)) |
| $42, any other byte | | a 2-byte no-operation, reserved |

**Shifts and rotates.** The count is taken modulo the width (0-7, 0-15 or
0-31). C is the last bit shifted out, or, of a rotate, the last bit carried
round (the new bit 0 of ROL, the new top bit of ROR); a count of 0 leaves C
alone. N and Z are of the result.

**Multiply and divide** take every addressing mode of the instruction
whose opcode follows the $42 (`MUL #`, `MUL dp`, `MUL abs,X`, `MUL [dp],Y`
...), the operand as wide as A, an immediate's too.

- `MUL`, `UML`: the double-width product's low half goes to A and its high
  half to X. N and Z are of A; V is set if the product does not fit A's
  width (signed or unsigned); C is unchanged.
- `DIV`, `UDV`: the quotient to A, the remainder to X. N and Z are of the
  quotient, C is unchanged. `DIV` rounds the quotient down (toward minus
  infinity), so the remainder has the divisor's sign: for a positive
  divisor these are Oberon's DIV and MOD, `-7 DIV 2 = -4`, `-7 MOD 2 = 1`
  *(decided)*. V is set on overflow (the most negative number divided by
  -1: A gets that number, X 0).
- A divisor of 0 sets V and changes nothing else.
- X gets as much of the high half or remainder as it holds: with an 8-bit
  index all but the low byte is lost.

They take about one cycle per bit of the width (below).

The data sheet reserves WDM "for future microprocessors" (8.17). The other
second bytes are left for more instructions; $01, $02 and $FF stay
no-operations, since em16's own processor (EmCPU, not `-fpga`) uses
`WDM #1`, `#2` and `#$FF` for host I/O.

### Code written before

A WDM used to be a 2-byte no-operation whatever its operand. Now
`WDM #$6D`, say, is the first two bytes of `MUL abs`. OS16 and MiniMon use
only `WDM #$B0` and `#$B1`, which are as they were.

## Cycles

Measured back to back (rdy high), as the README's table:

| | cycles |
|---|---|
| a 32-bit memory operand | 2 more than a 16-bit one |
| `BSW`, `XFE` | 2 |
| `ASL #n` ... `ROR #n` | 3, whatever *n* (one shifter) |
| `UML #` | *w* + 5 (37 at 32 bits, 21 at 16) |
| `MUL #`, `UDV #` | *w* + 7 |
| `DIV #` | *w* + 9 |

(*w* the width in bits.) A memory operand adds its reads, as for ADC.
The multiply and divide take a bit a cycle, with one adder between them:
small, and a match for the rest of the core's paths.

## Building

`cpu_65c816` has two parameters:

| | |
|---|---|
| `C832` (1) | the 65C832 modes; 0: E16 stays 1, XFE does nothing, and A, X and Y are 16 bits as before |
| `XOPS` (1) | MUL, UML, DIV, UDV, the shifts and BSW; 0: they are no-operations |

A parameter of 0 holds that part's registers constant, and synthesis drops
them. Gowin's synthesis of the SoC for the Tang Nano 20K (GW2AR-18, 20,736
logic cells, LUTs and ALUs), November 2026:

| C832 | XOPS | the CPU | the SoC |
|---|---|---|---|
| 0 | 0 | 4,562 (the 65C816 before: 4,531) | 17,999, 87% |
| 0 | 1 | 5,533 | about 18,970, 91% |
| 1 | 0 | 6,130 | about 19,570, 94% |
| 1 | 1 | about 7,760 | 21,196, 102%: it does not fit |

So the whole 65C832 does not fit beside the rest of the SoC on the Tang
Nano 20K; the system clock (40.5 MHz) already has about 6% to spare with
the 65C816. `fpga/rtl/soc.v` therefore builds the core with `C832=0` and
`XOPS=1`, a 65C816 with the extension: placed and routed, 18,847 cells
(91%), and the system clock makes 44.7 MHz (the 65C816 alone: 42.9). The
whole 65C832 waits for a larger FPGA, and em16 is to emulate it (the
plan, below).

`make test832` checks the core as its parameters default (both 1);
`make test816x` checks it as the Tang Nano builds it (`test832_gen.py
--c816`: the same checks without the 65C832 modes, and XFE doing
nothing).

## Plan

1. **The core** (this): the modes and the extension in `cpu_65c816.v`,
   checked by `make test832` (`test832_gen.py`: directed checks of every
   mode, and random MUL/DIV/shift/BSW cases at every width against
   Python's arithmetic), the TomHarte vectors for 65C816 behaviour, and a
   synthesis of the SoC (fit and timing on the Tang Nano 20K).
2. **em16** (65Tools): EmCore, which runs under `em16 -fpga`, does the
   same, and runs the same test images.
3. **The assembler** (65Tools `as`): `cpu="832"`, 32-bit immediates and
   `longa`/`longi` widths, the extension's mnemonics.
4. **OS16**: the 65C832 native vectors in the ROM, interrupts and task
   switches that keep A, X, Y whole and E16/E8, and HashCore's SHA-256 in
   32-bit mode, the first user.
5. **oc816**: an option to generate 65C832 code, LONGINT in a 32-bit
   accumulator and MUL/DIV for INTEGER and LONGINT.
